# AI Provider Port Implementation Guide

## Overview

Increment 4 implements **ADR-006** (optional AI), **ADR-007** (local-first with OpenAI default), and **ADR-008** (user-governed memory) with a complete AI provider system.

Key features:
- ✅ **Multiple provider support**: OpenAI (default), Ollama (local), None (fallback)
- ✅ **Graceful degradation**: AI unavailability never breaks core workflows
- ✅ **Circuit breaker pattern**: Health checks prevent cascading failures
- ✅ **Deterministic fallback**: NoOp adapter for testing and offline use
- ✅ **User-governed**: Provider selection via explicit configuration

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                    Application Layer                             │
│                (AiOrchestrationService)                         │
│  - Health monitoring via @Scheduled health checks               │
│  - Availability reporting for UI and observability              │
│  - Graceful degradation on provider failure                     │
└──────────────────────────┬──────────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────────┐
│                AiAssistantPort (Interface)                      │
│  Contract: suggestReflectiveQuestion(String) -> AiSuggestion   │
└──────────────────┬──────────────────────────────────────────────┘
                   │
      ┌────────────┼────────────┐
      ▼            ▼            ▼
  OpenAI       Ollama        NoOp
  Adapter      Adapter       Adapter
  (Cloud)      (Local)       (Fallback)
```

## Provider Selection

### Configuration (application.yml or environment)

```yaml
helix:
  ai:
    provider: openai              # Default: openai
    openai:
      api-key: ${OPENAI_API_KEY}  # Required for openai
      model: gpt-4o-mini
    ollama:
      base-url: http://localhost:11434
      model: llama2
```

### Provider Types

| Provider | Type | Requires | Use Case | Availability |
|----------|------|----------|----------|--------------|
| **openai** | Cloud LLM | OpenAI API key | Default for deployment | Requires network |
| **ollama** | Local LLM | Ollama running locally | Development, privacy | Requires local service |
| **none** | Deterministic | Nothing | Testing, offline | Always available |

## Setup Guide

### 1. OpenAI (Default Provider)

**Step 1: Get API Key**
- Create account at https://platform.openai.com
- Generate API key at https://platform.openai.com/account/api-keys
- Keep key secure (never commit to version control)

**Step 2: Configure**
```bash
cp .env.example .env
```

Then set your key in `.env`:

```bash
OPENAI_API_KEY=sk-...
```

`./scripts/dev-api` automatically loads `.env` from repository root.

Or in `application.yml`:
```yaml
helix:
  ai:
    provider: openai
    openai:
      api-key: ${OPENAI_API_KEY}
      model: gpt-4o-mini
```

**Step 3: Run Application**
```bash
./scripts/dev-api
```

### 2. Ollama (Local Development Alternative)

**Step 1: Install Ollama**
- Download from https://ollama.ai
- Or: `brew install ollama` (macOS)

**Step 2: Pull Model**
```bash
ollama pull llama2
# Or: ollama pull neural-chat, mistral, dolphin-mixtral, etc.
```

**Step 3: Start Ollama Service**
```bash
ollama serve
# Runs on http://localhost:11434 by default
```

**Step 4: Configure Helix**
```yaml
helix:
  ai:
    provider: ollama
    ollama:
      base-url: http://localhost:11434
      model: llama2
```

**Step 5: Run Application**
```bash
./scripts/dev-api
```

### 3. Deterministic Fallback (Testing/Offline)

**Configuration:**
```yaml
helix:
  ai:
    provider: none
```

No external dependencies required. AI port always returns deterministic suggestions.

## Fallback Behavior

All providers implement graceful degradation:

1. **Request succeeds**: AI generates suggestion, marked as non-fallback
2. **Provider timeout/error**: Circuit breaker triggers fallback
3. **Health check fails**: Fallback used for subsequent requests
4. **Recovery**: After 30 seconds of silence, health check re-enabled

```java
// Example: OpenAI timeout → fallback
AiSuggestion suggestion = aiPort.suggestReflectiveQuestion(context);

if (suggestion.deterministicFallback()) {
    // Was generated without AI
    // Safe to use in UI, log as "AI unavailable"
} else {
    // Was generated by AI provider
    // Mark as AI-assisted in any persistent records
}
```

## Monitoring & Diagnostics

### Health Check Endpoint

```java
orchestrationService.getDiagnostics()
// Returns:
// {
//   activeProvider: "openai",
//   overallHealth: true,
//   openaiHealthy: true,
//   ollamaHealthy: false
// }
```

### Logs

- Provider initialization: `"AI Provider initialized: openai (model: gpt-4o-mini)"`
- Provider failure: `"AI Provider openai became unavailable"`
- Provider recovery: `"AI Provider openai recovered"`
- Configuration errors: `"OpenAI configuration invalid (missing API key). Falling back to NoOp adapter."`

## Testing Strategy

### Unit Tests (Provided)
- `NoAiAssistantAdapterTest`: Deterministic fallback behavior
- `OpenAiAssistantAdapterTest`: OpenAI adapter compliance
- `OllamaAssistantAdapterTest`: Ollama adapter behavior
- `AiProviderFactoryTest`: Correct adapter selection
- `AiOrchestrationServiceTest`: Health monitoring and diagnostics

### Integration Tests (Recommended)
- Test with real OpenAI API (integration test suite)
- Test with local Ollama (local development)
- Test circuit breaker with artificial delays/errors
- Test provider switching at runtime

### Chaos Tests (Recommended)
- Simulate OpenAI timeout (kill provider, verify fallback)
- Simulate Ollama connection refused (verify graceful degradation)
- Test concurrent requests during provider failure
- Test rapid provider health transitions

## Governance & Privacy

**Governed by ADR-008: User-Governed AI Memory**

- AI suggestions are **not** persisted by default
- AI output can enhance UX (e.g., "Here's an AI-assisted reflection")
- User must explicitly **accept** AI suggestions to persist them
- All AI records preserve:
  - Provider name (openai, ollama, none)
  - Model version
  - Confidence flag (non-fallback = higher confidence)
  - Provenance link to source reflection/context

**Logging Privacy**
- User reflections, prompts, and journal content are **never logged**
- Only provider diagnostics (health, errors, response times) are logged
- AI API calls are logged at DEBUG level only (disabled by default)

```yaml
      thread-name-prefix: "helix-ai-"
```

## Troubleshooting

### Issue: "OpenAI configuration invalid (missing API key)"
**Cause**: `OPENAI_API_KEY` environment variable not set or empty

**Solution**:
```bash
cp .env.example .env
OPENAI_API_KEY=sk-...
./scripts/dev-api
```

### Issue: "Ollama is not running"
**Cause**: Provider set to `ollama` but service not available

**Solution**:
```bash
ollama serve
# In another terminal:
./scripts/dev-api
```

### Issue: Suggestions always return deterministic fallback
**Cause**: Provider configured but not available, falling back gracefully

**Check**: 
```java
orchestrationService.getDiagnostics()
// Look at overallHealth and provider-specific health
```

### Issue: OpenAI API returns 401 Unauthorized
**Cause**: API key is invalid or expired

**Solution**:
- Verify key from https://platform.openai.com/account/api-keys
- Check for expiration or usage limits
- Generate new key if needed
